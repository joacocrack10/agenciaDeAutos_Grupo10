Guía de estudio · solo React

El código de src

En la defensa se abre la carpeta lujo-lujitos-react/src y se explica ese JavaScript. Esta guía recorre cada .jsx y cada .js de ahí: qué exporta, qué estado tiene, qué props recibe y a qué otro archivo llama. Los estilos, las fotos y la configuración de Vite no son el código que hay que explicar.

Qué código es de cada uno

Hay una sola app. App.jsx elige la página. Cada uno explica los archivos que escribió.

Lo que React hace en esta app

Un componente es una función que devuelve JSX. JSX parece HTML y es JavaScript: class se escribe className, for se escribe htmlFor, y { } mete una variable o una expresión. Varios hermanos se envuelven en <>...</>. El comentario adentro del JSX es {/* así */}.

Props. Argumentos que el padre le pasa al hijo. App le pasa sesion a Barra. El hijo las lee y no las declara.

useState. const [valor, setValor] = useState(inicial). Para cambiar la pantalla se llama al setter. Leer la variable no alcanza. Cuando el componente se desmonta, ese estado desaparece, salvo que se haya copiado a localStorage.

useEffect. Corre después de dibujar. [] significa una vez, al aparecer. Si el efecto devuelve una función, esa función es la limpieza. En el hero limpia el intervalo. En el turno limpia el listener de Escape.

Input controlado. value={estado} y onChange que actualiza ese estado. El login y el turno están escritos así. Si falta el onChange, la letra no queda.

map y key. map convierte un array en elementos. Cada uno lleva key con un id estable. filter se queda con una parte del array. La galería filtra marcas y después las mapea.

Export. export default se importa sin llaves. export const marcas se importa entre llaves: import { marcas } from '../data/modelos'.

Router. BrowserRouter en main.jsx escucha la URL. Routes y Route en App.jsx eligen un componente. Link cambia la URL sin pedir otro HTML. useLocation() lee el path actual.

Cómo viajan los datos

  1. De padre a hijo, por props. modo nace en Raiz y baja a App y de ahí a Barra. sesion nace en App y baja a Barra, Inicio, Hero y Login.
  2. De hijo a padre, por una función. La barra no hace setModo. Llama a cambiarModo, que Raiz le pasó. El login no guarda la sesión él mismo: llama a setSesion, que es el setter de App.
  3. Entre archivos, por import. citas.js importa marcas de modelos.js y arma la lista del select. No pasa por props.
  4. Entre recargas, por localStorage. Tres claves: modo, sesion y turnos. El filtro de la galería y el texto a medio escribir no se guardan.

Joaquin

Su React es el arranque, el tema, la sesión, la barra y la home. App.jsx también declara las rutas /galeria, /turno y /admin: eso es el enchufe. El código de adentro de esas páginas es de Franco y de Teo.

src/main.jsx

Primer archivo de React. No dibuja la home. Crea la raíz, el router y el tema, y renderiza App.

const [modo, setModo] = useLocalStorage('modo', 'dark');

const tema = useMemo(
  () => createTheme({
    palette: {
      mode: modo,
      primary: { main: '#ff1f3d', contrastText: '#0a0a0c' },
      ...(modo === 'dark' && {

  • useLocalStorage('modo', 'dark') devuelve el mismo par que useState. El segundo argumento es el valor si todavía no hay nada guardado.
  • useMemo(..., [modo]) arma el objeto del tema solo cuando cambia el modo. createTheme no corre en cada render.

  • CssBaseline aplica el color de fondo del tema al body.

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <BrowserRouter>
      <Raiz />
    </BrowserRouter>
  </StrictMode>
);

createRoot agarra el div vacío y a partir de ahí pinta React. BrowserRouter envuelve todo porque Link, Routes y useLocation tienen que estar adentro. StrictMode en desarrollo ejecuta algunos efectos dos veces para detectar limpiezas que faltan. En la pantalla no se ve.

Si piden «dónde está el color de la app», es este createTheme. Si piden «quién envuelve las rutas», es este BrowserRouter.

src/App.jsx

Recibe modo y cambiarModo. Dueño de la sesión y de si el login está abierto.

const [sesion, setSesion] = useLocalStorage('sesion', null);
const [loginAbierto, setLoginAbierto] = useState(false);
const { pathname } = useLocation();
const abrirLogin = () => setLoginAbierto(true);

sesion sobrevive al F5 porque pasa por el hook. loginAbierto es un useState común: al recargar el cuadro empieza cerrado, aunque la persona siga logueada.

ScrollArriba está en el mismo archivo. Hace return null. Su efecto depende de pathname y llama a window.scrollTo(0, 0). Sirve para que al cambiar de ruta la ventana vuelva arriba. No genera etiquetas.

Lo que renderiza App, en este orden:

  1. Barra con modo, cambiarModo, sesion y abrirLogin.
  2. Cinco rutas. Inicio recibe sesion y abrirLogin. Galeria, Turno y Admin no reciben props. path="*" es cualquier otra URL y renderiza NoEncontrada.
  3. Login siempre está montado. Se ve cuando abierto={loginAbierto} es true. Recibe cerrar, sesion y setSesion.
  4. {pathname === '/' && <Pie />}. En las otras rutas esa expresión es false y React no dibuja el pie.

src/hooks/useLocalStorage.js

Función que usa hooks. La usan main.jsx (clave modo) y App.jsx (clave sesion). Las citas no la usan.

export default function useLocalStorage(clave, valorInicial) {
  const [valor, setValor] = useState(() => {
    try {
      const texto = localStorage.getItem(clave);
      return texto ? JSON.parse(texto) : valorInicial;
    } catch {
      return valorInicial;
    }
  });

  useEffect(() => {
    if (valor === null) localStorage.removeItem(clave);
    else localStorage.setItem(clave, JSON.stringify(valor));
  }, [clave, valor]);

  return [valor, setValor];
}
  • La función que se le pasa a useState corre una sola vez. Ahí se lee el navegador. JSON.parse convierte el texto en un valor de JavaScript.
  • Si el texto guardado está roto, el catch usa el valor inicial y la app no se cae.
  • El efecto corre después del primer render y cada vez que cambian clave o valor. null borra la clave. Cualquier otro valor se guarda con JSON.stringify.
  • Devuelve el mismo par que useState, así el componente que lo llama escribe const [sesion, setSesion] = useLocalStorage(...).

Cerrar sesión es setSesion(null). El efecto ve el null y hace removeItem('sesion').

src/data.js

No es un componente. No tiene JSX. Exporta tres constantes que los componentes de la home importan.

  • horarios. De lunes a sábado. dia usa el número de Date.getDay(): 1 es lunes, 6 es sábado. No hay objeto para el domingo (0), así que ese día el chip queda cerrado. desde y hasta son horas enteras. Lunes a viernes 9–19. Sábado 10–14. diaTexto y atencion son lo que muestra la tabla.
  • autos. Tres objetos: Porsche 911, Mercedes-AMG GT 63 S, Ferrari 296 GTB. Cada uno tiene id, marca, modelo, imagen, specs y precio. specs es un array de pares [etiqueta, valor]. El precio ya es un string, por ejemplo '$130,000'.
  • beneficios. Tres objetos con id, titulo, imagen y texto.

Este array de tres autos no alimenta el select del turno. El turno importa marcas desde modelos.js.

src/components/Hero.jsx

Props: sesion, abrirLogin. Estado: abierto, boolean, empieza en false.

useEffect(() => {
  function revisarHorario() {
    const ahora = new Date();
    const dia = ahora.getDay();
    const hora = ahora.getHours();
    setAbierto(horarios.some((h) => h.dia === dia && hora >= h.desde && hora < h.hasta));
  }
  revisarHorario();
  const intervalo = setInterval(revisarHorario, 60000);
  return () => clearInterval(intervalo);
}, []);

some devuelve true si algún horario cumple las tres condiciones. La hora hasta no entra: a las 19 el chip ya dice CERRADO. El efecto corre al montar, repite cada 60 segundos y la función devuelta corta el intervalo cuando el hero se va. Importa horarios de ../data.

El chip usa el estado: label={abierto ? 'ABIERTO' : 'CERRADO'}. «Explorar Modelos» y «Tour Virtual» son Button component={Link} to="/galeria". El botón de sesión no navega: onClick={abrirLogin}, y el texto es sesion ? 'Mi cuenta' : 'Iniciar Sesión'. El correo no se muestra acá. Se muestra en Barra.

src/components/Login.jsx

Props: abierto, cerrar, sesion, setSesion. Estado local: email, password, acepto, error. Los cuatro empiezan vacíos o en false y se pierden al recargar. La sesión que queda es la de App.

Si sesion tiene valor, el diálogo muestra «Tu cuenta», el email y un botón que llama a cerrarSesion. Esa función es setSesion(null).

Si no hay sesión, hay un form controlado. Cada TextField tiene value y onChange que hace setEmail o setPassword. El checkbox hace setAcepto(e.target.checked).

function manejarEnvio(e) {
  e.preventDefault();
  if (!acepto) {
    setError('Tenés que aceptar los términos para ingresar.');
    return;
  }
  setSesion({ email: email.trim() });
  setEmail('');
  setPassword('');
  setAcepto(false);
  setError('');
  cerrar();
}
  • preventDefault frena el envío nativo del form, que recargaría la página.
  • Sin el checkbox, hay error y un return. No se llama a setSesion.
  • El objeto guardado tiene una sola propiedad, email, ya sin espacios. password se limpia y no se copia.
  • cerrar es la prop de App: pone loginAbierto en false.

Los campos tienen required y el correo tiene type="email". Esa validación la hace el navegador antes de disparar onSubmit: no deja mandar el form vacío. El código de React no compara la contraseña contra una lista. Cualquier contraseña no vacía, con los términos aceptados, entra.

El recorrido completo: click en la barra → abrirLogin → loginAbierto true → el Dialog se abre → submit → setSesion → el hook escribe sesion → la barra se redibuja con sesion.email.

src/pages/Turno.jsx

Importa guardarCita y modelosDisponibles desde ../data/citas.

const [formData, setFormData] = useState({
  nombre: '',
  telefono: '',

modelo arranca con el nombre del primer auto. ?. corta si la lista viniera vacía, y ?? '' deja string vacío en ese caso. El resto del estado es minDate, isSubmitting, btnText, showModal y modalData.

Fecha mínima

useEffect(() => {
  const now = new Date();
  const month = String(now.getMonth() + 1).padStart(2, '0');
  const day = String(now.getDate()).padStart(2, '0');
  setMinDate(`${year}-${month}-${day}T${hours}:${minutes}`);

Los meses de getMonth van de 0 a 11, por eso el + 1. padStart agrega el cero. El input datetime-local recibe ese string en min={minDate}. El efecto tiene []: calcula «ahora» una vez, al entrar.

Cambios del formulario

const handleChange = (e) => {
  const { id, value } = e.target;
  setFormData((prev) => ({ ...prev, [id]: value }));
};

Nombre, modelo y fecha usan este handler. El id del input coincide con la clave del objeto (nombre, modelo, fecha). ...prev copia los otros campos. [id] escribe solo el que cambió. Sin el spread, el estado se quedaría con un único campo.

El teléfono tiene su propio handler:

const limpio = e.target.value.replace(/[^\d+\s()-]/g, '').slice(0, 20);
setFormData((prev) => ({ ...prev, telefono: limpio }));

La expresión regular se queda con dígitos, +, espacios, paréntesis y guiones. slice(0, 20) corta en 20 caracteres. El resultado vuelve a formData.telefono, y el input lo muestra porque es controlado: value={formData.telefono}.

Submit

const handleSubmit = async (e) => {
  e.preventDefault();
  const fechaFormat = new Date(formData.fecha).toLocaleDateString('es-ES', { ... });
  setIsSubmitting(true);
  guardarCita({
    nombre: formData.nombre.trim(),
    telefono: formData.telefono,
    modelo: formData.modelo,
    fecha: formData.fecha,
    fechaFormateada: fechaFormat,
    creadoEn: new Date().toISOString()
  });
  setTimeout(() => { /* cambia el texto del botón y, un segundo después, abre el cartel */ }, 800);
};
  • preventDefault evita que el form navegue.
  • guardarCita corre en el momento. El cartel espera los dos setTimeout (800 ms y después 1000 ms). Esos timeouts cambian btnText y después ponen showModal en true. No consultan un servidor.
  • modalData guarda nombre, modelo y la fecha ya formateada. El cartel lee modalData, no formData.
  • isSubmitting deshabilita el botón con disabled={isSubmitting} mientras tanto.

En el JSX cada campo tiene value={formData....}. Nombre, teléfono, modelo y fecha son required. Nombre además tiene minLength={3}. El select es:

{modelosDisponibles.map((item) => (
  <option key={item.id} value={item.nombre}>{item.nombre}</option>
))}

El value del option es el nombre. Eso es lo que queda en formData.modelo y después en la cita.

closeModal reinicia formData con el primer modelo otra vez y pone showModal en false. El link «Ver en la agenda» es <Link to="/admin">.

El segundo efecto depende de [showModal]. Si el cartel está abierto y la tecla es Escape, llama a closeModal. Devuelve una función que hace removeEventListener. Sin esa limpieza, cada vez que se abre el cartel se sumaría otro listener.

src/data/citas.js

No dibuja. Es el único archivo que toca la clave turnos.

import { marcas } from './modelos'
const CLAVE = 'turnos'

export const modelosDisponibles = marcas.flatMap((marca) =>
  marca.modelos.map((modelo) => ({ id: modelo.id, nombre: modelo.nombre }))
)

map solo dejaría un array por marca. flatMap los junta en una sola lista de { id, nombre }. El turno la recorre para los option. No copia motor ni precio.

Si no hay nada guardado, o si lo guardado no es un array, leerCitas devuelve []. El catch cubre un JSON roto. Admin puede hacer .map y .length sin preguntar si vino null.

export function leerCitas() {
  try {
    const texto = localStorage.getItem(CLAVE);
    const datos = texto ? JSON.parse(texto) : [];
    return Array.isArray(datos) ? datos : [];
  } catch {
    return [];
  }
}

export function guardarCita(cita) {
  const citas = leerCitas();
  const nueva = { id: crypto.randomUUID(), ...cita };
  localStorage.setItem(CLAVE, JSON.stringify([...citas, nueva]));
  return nueva;
}

export function borrarCita(id) {
  const citas = leerCitas().filter((cita) => String(cita.id) !== String(id));
  localStorage.setItem(CLAVE, JSON.stringify(citas));
  return citas;
}
  • guardarCita lee, agrega y escribe el array entero. crypto.randomUUID() genera el id. El spread ...cita copia nombre, teléfono, modelo y fechas.
  • [...citas, nueva] es un array nuevo. No se hace push sobre el anterior.
  • borrarCita se queda con las citas cuyo id es distinto. Compara como string. Devuelve la lista nueva para que Admin haga setTurnos con ella.

Este import de marcas es el cruce con el código de Franco. El select de Teo muestra los mismos autos que la galería porque los dos leen modelos.js.

const [turnos, setTurnos] = useState([]);

  setTurnos(leerCitas());
}, []);

const handleEliminar = (id) => {

Al montar, el efecto lee localStorage una vez y copia el array al estado. La tabla se dibuja desde turnos, no leyendo el storage en el render.

window.confirm es del navegador. Si la persona elige cancelar, devuelve false y el return corta: no se llama a borrarCita. Si acepta, borrarCita escribe el storage y devuelve el array que queda. setTurnos con ese array vuelve a dibujar la tabla.

Si turnos.length === 0, se renderiza el párrafo «No hay turnos registrados en este momento.». Si hay elementos, turnos.map con key={item.id} arma las filas: item.nombre, item.telefono, item.modelo, item.fechaFormateada || item.fecha, y un botón cuyo onClick es () => handleEliminar(item.id).

Admin no recibe sesion. No filtra citas por persona. Muestra todo lo que hay en la clave turnos de este navegador.

Preguntas sobre este código

  • ¿Dónde se monta React? En main.jsx, createRoot(...).render(...).
  • ¿Quién elige la página? <Routes> en App.jsx. El que escucha la URL es BrowserRouter, en main.jsx.
  • ¿Por qué la sesión sigue al ir a la galería? Porque vive en App, y App no se desmonta. Lo que se desmonta es el componente de la ruta.
  • ¿Qué es una prop en este proyecto? Por ejemplo sesion, que App le pasa a Barra, y marca, que Galeria le pasa a SeccionMarca.
  • ¿Dónde hay un input controlado? En Login.jsx (value={email}) y en Turno.jsx (value={formData.nombre} y el resto de formData).
  • ¿Dónde hay un useEffect con limpieza? En Hero.jsx (clearInterval) y en Turno.jsx (removeEventListener).
  • ¿Por qué la key es el id? Porque el id no cambia cuando la lista se filtra o se achica. El índice del array sí cambia.
  • ¿Dónde se escribe la cita? guardarCita en citas.js, llamada desde handleSubmit de Turno.jsx. La lee leerCitas, llamada en el efecto de Admin.jsx.
  • ¿Por qué el select muestra un auto de la galería? Porque modelosDisponibles hace flatMap de marcas, y marcas está exportado por modelos.js.
  • ¿La contraseña queda guardada? No. setSesion recibe solo { email }.
  • ¿Qué estado se pierde al recargar? loginAbierto, marcaSeleccionada, formData y showModal. Siguen modo, sesion y turnos.
